# Rubric: privacy.third-party-data — User data sent to third parties

Many tools added to a site quietly receive visitors' personal details: an analytics event with an email in it, a chat widget given the user's name and phone, an AI prompt with the user's notes. Visitors haven't agreed to that, and the owner often doesn't know it's happening.

You were given the code that calls outside services (from the browser and from the server).

First list every outside service that receives data, and name them in the `why` of question 1.

1. **Is personal data sent to analytics, ads or session-replay tools?**
   Fail: `track("signup", { email })`, `gtag("event", …, { phone })`, `identify(user.email, …)` with raw email, phone or name; the full page address with personal data in the query string sent as a page view.
   Pass: only an anonymous id or a hashed value, or nothing personal.
2. **Is user content sent to an AI or other processing service without the user knowing?**
   Fail: notes, messages, documents or uploads sent to OpenAI, Anthropic or similar, with nothing in the interface or the policy saying so.
   Pass: the interface says it ("answers are generated by AI"), or nothing personal is sent.
3. **Is more sent than the service needs?**
   Fail: the whole user object (`JSON.stringify(user)`) or a full form sent to a chat, CRM or webhook that only needs a name and email.
   Pass: only the fields the service needs.
4. **Do outside services get data before the visitor agrees, where consent is needed?**
   Fail: ad and analytics tools receive identifiers before the cookie choice. Answer `pass` with "Doesn't apply:" when the site uses no such tools.
   Pass: they start only after consent.

Findings: one for each service that gets too much, quoting the line that sends it. Options: (1) send only what's needed, or an anonymous id (recommended); (2) keep it and say so in the privacy policy; (3) remove the service.
